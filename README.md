# Zigbee Environment Station

Система мониторинга и управления Zigbee‑устройствами с открытой архитектурой.  
Собирает данные с датчиков (температура, влажность, протечки, движение и др.) через Zigbee2MQTT, передаёт их через Kafka в TimescaleDB и предоставляет веб‑интерфейс администрирования (Django) и визуализацию (Grafana).

## Архитектура

```
┌─────────────┐     ┌──────────────┐     ┌─────────┐     ┌──────────────┐     ┌─────────────┐
│ Zigbee      │────▶│ Mosquitto    │────▶│ Kafka   │────▶│ TimescaleDB  │────▶│ Grafana     │
│ устройства  │     │ (MQTT broker)│     │         │     │(гипертаблица)│     │ (дашборды)  │
└─────────────┘     └──────────────┘     └─────────┘     └──────────────┘     └─────────────┘
       │                    │                 │                   │                   │
       │                    │                 │                   │                   │
       ▼                    ▼                 ▼                   ▼                   ▼
┌─────────────┐     ┌──────────────┐     ┌─────────┐     ┌──────────────┐     ┌─────────────┐
│ Zigbee2MQTT │     │ Kafka‑       │     │ Kafka‑  │     │ Django‑панель│     │ Nginx       │
│             │     │ producer     │     │ consumer│     │ (админка)    │     │ (прокси)    │
└─────────────┘     └──────────────┘     └─────────┘     └──────────────┘     └─────────────┘
```

Данные проходят через несколько слоёв обработки:
1. **Zigbee2MQTT** – мост между Zigbee‑координатором и MQTT.
2. **Mosquitto** – MQTT‑брокер, центральная шина сообщений.
3. **Kafka‑producer** – подписывается на все MQTT‑топики, обогащает метаданными и отправляет в Kafka.
4. **Kafka** – буферизирует поток сообщений, обеспечивает отказоустойчивость.
5. **Kafka‑consumer** – читает топик Kafka, парсит сообщения и сохраняет в TimescaleDB.
6. **TimescaleDB** – база данных временных рядов, оптимизированная для хранения метрик.
7. **Django‑панель** – управление устройствами, просмотр статистики, настройка.
8. **Grafana** – построение дашбордов в реальном времени.
9. **Nginx** – проксирует запросы к Django‑панели, раздаёт статику.

## Структура проекта

Все компоненты контейнеризированы с помощью Docker и оркестрируются через `docker-compose.yml`.  
Папки первого уровня соответствуют отдельным сервисам или конфигурациям:

### Корневые файлы
- `docker-compose.yml` – основной файл оркестрации.
- `Makefile` – вспомогательные команды (`make up`, `make down`, `make migrate` и т.д.).
- `.env` – переменные окружения для запуска (копия `env.template`).
- `env.template` – шаблон переменных окружения.
- `pyproject.toml` – метаданные проекта и общие Python‑зависимости (для Django и симулятора).
- `README.md` – этот файл.

### Сервисы

#### `zigbee2mqtt/`
Содержит конфигурацию для **Zigbee2MQTT** – сервиса, который взаимодействует с Zigbee‑координатором (ZBDongle‑P / ZG‑808Z) и преобразует Zigbee‑сообщения в MQTT.  
Ключевые файлы:
- `configuration.yaml` – настройки: порт координатора, MQTT‑сервер, шаблоны сообщений.
- `coordinator_backup.json` – резервная копия сети Zigbee.
- `state.json` – кэш последних состояний устройств.

#### `mosquitto/`
Конфигурация MQTT‑брокера **Eclipse Mosquitto**.  
- `config/mosquitto.conf` – слушает порты 1883 (MQTT) и 9001 (WebSockets), разрешает анонимные подключения (для разработки).

#### `kafka_producer/`
**Kafka‑producer** – Python‑сервис, который подписывается на MQTT‑топики (`zigbee2mqtt/#`) и отправляет каждое сообщение в Kafka (топик `sensor-raw`).  
Обогащает сообщение метаданными: IEEE‑адрес, время получения, источник.  
- `main.py` – основной код.
- `Dockerfile`, `requirements.txt`.

#### `kafka_consumer/`
**Kafka‑consumer** – читает топик `sensor-raw`, парсит сообщения и записывает в TimescaleDB.  
Поддерживает пакетную вставку (`batch_size`), обработку ошибок.  
- `main.py` – логика потребления и записи.
- `Dockerfile`, `requirements.txt`.

#### `postgres/`
Скрипты инициализации для **TimescaleDB** (расширение PostgreSQL для временных рядов).  
- `docker-entrypoint-initdb.d/init.sql` – создаёт гипертаблицу `sensor_measurements`, индексы, политики сжатия, вспомогательные функции и представления.

#### `grafana/`
Конфигурация **Grafana**: дашборды и источники данных.  
- `provisioning/datasources/postgres.yml` – подключает TimescaleDB как источник.
- `provisioning/dashboards/` – JSON‑модели дашбордов (`sensor_overview.json`) и провайдер.
- `config/grafana.ini` – основные настройки (учётные данные по умолчанию: `admin` / `admin123`).

#### `django/`
**Django‑приложение** для администрирования устройств, просмотра событий и статистики.  
Структура внутри соответствует стандартному Django‑проекту:
- `config/` – настройки, URL‑маршруты.
- `apps/` – пользовательские приложения:
  - `locations` – иерархия помещений.
  - `devices` – модели Zigbee‑устройств, измерений, событий, MQTT‑клиент.
  - `timemarkers` – ручные временные метки (например, начало отопления).
- `templates/` – кастомные шаблоны админки.
- `manage.py`, `requirements.txt`.

#### `sensor_simulator/`
**Симулятор Zigbee‑устройств** для разработки и тестирования (профиль `dev`).  
Генерирует фейковые данные от датчиков разных типов (температура, движение, протечка, выключатель, модуль выключателя ZG‑301Z) и публикует их в MQTT.  
- `main.py` – основной цикл.
- `devices/` – классы, имитирующие конкретные устройства.
- `config.py`, `mqtt_client.py`.

#### `nginx/`
**Nginx** – прокси‑сервер для Django‑панели.  
- `nginx.conf` – проксирует запросы на `admin-panel`, раздаёт статику.

#### `zookeeper/` (создаётся при запуске)
Данные ZooKeeper (используется Kafka). Не включается в репозиторий.

#### `kafka/` (создаётся при запуске)
Данные Kafka. Не включается в репозиторий.

### Файлы окружения
- `.gitignore` – исключает временные файлы, данные БД, виртуальные окружения, папки `kafka/`, `zookeeper/` и т.д.
- `Dockerfile.django` – альтернативный Dockerfile для Django (используется реже, основной в `django/Dockerfile`).

## Запуск проекта

### Требования
- Docker и Docker Compose (версия 3.8+)
- Для работы с реальными Zigbee‑устройствами: координатор (например, ZBDongle‑P) подключён к хосту.

### Переменные окружения
Скопируйте `env.template` в `.env` и при необходимости отредактируйте:
```bash
cp env.template .env
```

Основные переменные:
- `COMPOSE_PROFILES` – выбор запускаемых сервисов (например, `telemetry,dev-ui,ui,dev` для полной разработки).
- `POSTGRES_*` – параметры подключения к TimescaleDB.
- `KAFKA_*` – настройки Kafka.
- `MQTT_*` – параметры MQTT‑брокера.
- `SIMULATOR_*` – настройки симулятора (количество устройств, интервал, типы).

### Команды Makefile
- `make up` – запустить все сервисы (docker compose up -d).
- `make down` – остановить и удалить контейнеры, очистить данные Kafka и Zookeeper.
- `make ps` – показать состояние контейнеров.
- `make migrate` – выполнить миграции Django.
- `make makemigrations` – создать новые миграции Django.
- `make new-device` – разрешить присоединение новых устройств на 120 секунд (отправляет MQTT‑команду в zigbee2mqtt).

### Профили Docker Compose
Сервисы распределены по профилям:
- `telemetry` – база данных, Kafka, потребители (ядро системы).
- `ui` – Grafana.
- `dev-ui` – Kafka‑UI.
- `dev` – симулятор датчиков.
- `processing` – Django‑панель и Nginx.
- `production` – Zigbee2MQTT (для работы с реальными устройствами).

Пример запуска с полным набором для разработки:
```bash
export COMPOSE_PROFILES=telemetry,dev-ui,ui,dev,processing
docker compose up -d
```

Для продакшена обычно достаточно:
```bash
export COMPOSE_PROFILES=telemetry,ui,processing,production
docker compose up -d
```

## Управление устройствами через MQTT

Команды отправляются в топик `zigbee2mqtt/<IEEE_АДРЕС>/set` с JSON‑пейлоадом.

Пример для модуля выключателя ZG‑301Z:
```bash
mosquitto_pub -h localhost -p 1883 -t "zigbee2mqtt/0xa4c138e53b478e15/set" -m '{"state": "ON"}'
```

Поддерживаемые команды:
- `{"state": "ON"}` / `{"state": "OFF"}` / `{"state": "TOGGLE"}`
- `{"countdown": 300}` (обратный отсчёт до выключения, сек)
- `{"power_on_behavior": "previous"}` (поведение при включении: `off`, `previous`, `on`)
- `{"switch_type": "toggle"}` (тип переключателя: `toggle`, `state`, `momentary`)

## Мониторинг и отладка

- **Grafana** – http://localhost:3003 (логин/пароль: admin/admin123)
- **Kafka‑UI** – http://localhost:8088 (если запущен профиль `dev-ui`)
- **Django‑админка** – http://localhost (через Nginx) или http://localhost:8010 (напрямую)
- **Логи контейнеров** – `docker compose logs -f <service>`

## Примечания по разработке на macOS
- Нет возможности пробросить usb порт в docker, в следствие чего zigbee2mqtt запускаестя нативно.
- В `zigbee2mqtt/configuration.yaml` указан последовательный порт `/dev/tty.usbserial-2130` – измените на свой.
- В `.env` можно настроить количество симулируемых устройств (`SIMULATOR_NUM_DEVICES`) и их типы (`SIMULATOR_DEVICE_TYPES`).
- Для работы с реальными устройствами отключите симулятор (не включайте профиль `dev`).
