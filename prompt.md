1) Система измерения параметров среды на Zigbee
1) Архитектура: Docker-compose, Kafka, Django (ядро), Postgres/TimescaleDB, Grafana
1) Единая кодовая база, два инстанса: data-consumer (Celery) и admin-panel (Django)
1) Zigbee2MQTT как софт для координатора
1) Устройства делятся на: управляемые (актуаторы) и неуправляемые (датчики)
1) Основные сущности: PhysicalQuantity, ZigbeeDevice, SensorType, SensorCorrection, DeviceCommand, Automation
1) Управляющие команды отправляются напрямую в MQTT (минуя Kafka)
1) Координатор: Sonoff ZBDongle-P (Zigbee 3.0 USB)
1) Датчики: noname температурные датчики (Zigbee 3.0, IEEE 802.15.4)
1) Требуется сервис-симулятор датчиков, отправляющий данные в MQTT
1) Использовать UV и pyproject.toml для управления зависимостями и виртуальными окружениями
1) Использовать .env и env.template для конфигурации переменных окружения
1) Использовать Docker Compose profiles:
1) production - реальные датчики + kafka-producer (без эмулятора)
1) dev - эмулятор датчиков (без kafka-producer и реальных датчиков)
1) Использовать provisioning дашбордов в Grafana
1) Не использовать init.py файлы (или оставлять их пустыми)
1) Не использовать относительные импорты. Все импорты описывать в начале файла



КОНТЕКСТ ПРОЕКТА
🎯 СУТЬ ПРОЕКТА
Zigbee Environment Station - система мониторинга и управления Zigbee устройствами умного дома. Позволяет собирать, хранить, анализировать и визуализировать данные с датчиков через MQTT → Kafka → TimescaleDB → Grafana, с Django админкой для управления метаданными.

🏗️ ОПИСАНИЕ СЕРВИСОВ (работающих)
text
✅ 1. MQTT брокер (Mosquitto)
   - Принимает данные от симулятора/реальных устройств
   - Порт 1883 (MQTT), 9001 (WebSockets)

✅ 2. Sensor Simulator (DEV профиль)
   - Генерирует реалистичные данные датчиков
   - Температура, влажность, движение, освещенность, энергопотребление
   - Отправляет в MQTT

✅ 3. Kafka + Zookeeper
   - Очередь сообщений для обработки данных
   - Топик: sensor-raw

✅ 4. Kafka Producer (MQTT → Kafka)
   - Мост между MQTT и Kafka
   - Обогащает данные метаданными

✅ 5. Kafka Consumer (Kafka → TimescaleDB)
   - Читает данные из Kafka
   - Сохраняет в TimescaleDB с пакетной вставкой

✅ 6. TimescaleDB (PostgreSQL + расширение)
   - Хранилище временных рядов
   - Таблица: sensor_measurements с гипертаблицей
   - Компрессия через 30 дней

✅ 7. Grafana
   - Визуализация данных
   - Дашборд "Zigbee Датчики - Мониторинг"
   - Источник данных: PostgreSQL/TimescaleDB

✅ 8. Redis
   - Кеш и брокер для Celery (в будущем)

✅ 9. Django (базовый)
   - Заготовка проекта (пока без функционала)

🎯 КЛЮЧЕВЫЕ ТЕХНИЧЕСКИЕ РЕШЕНИЯ
Одна БД - Django + TimescaleDB в одном PostgreSQL

Фильтрация в консьюмере - только известные IEEE адреса

Симуляторные устройства - model="virtual device" → is_simulated=True

Калибровка - линейная: value * multiplier + offset

TimeMarkers - привязка к устройствам/сенсорам (опционально)

Объем данных - ~20 устройств × 6 записей/мин = 86MB/день
